## 1. Ключевые решения в одном абзаце

Нативное macOS-приложение (SwiftUI + точечно AppKit), минимальная версия macOS 13, универсальная сборка (arm64 + x86_64). Вся математика — в Swift Package `SSMTCore` без зависимостей от UI и Core Audio, полностью покрытом тестами. Аудио — напрямую через Core Audio HAL (AUHAL), а не через AVAudioEngine: нужен точный выбор каналов, единые часы входа и выхода и отсчётно-точная привязка генератора к захвату. Режим референса по умолчанию — **B «Внутренний референс»** с блокировкой задержки (delay lock) на всю сессию мастера (см. раздел 4). Внешних runtime-зависимостей — **ноль**; из build-time инструментов — только XcodeGen (генерация `.xcodeproj` из текстового `project.yml`, чтобы проект нормально жил в git и собирался в CI).

## 2. Технологии и обоснование

| Область | Выбор | Почему |
|---|---|---|
| Язык | Swift 5.10+ (toolchain Xcode 16), language mode 5 | Строгая конкурентность Swift 6 включаем модульно, по мере готовности; аудио-поток всё равно требует ручной дисциплины |

| DSP | Accelerate / vDSP (`vDSP.FFT`, `vDSP_DFT_zrop`, векторные операции) | Быстро, без зависимостей, одинаково на arm64 и x86_64 |
| Аудио I/O | Core Audio HAL: `AudioUnit` `kAudioUnitSubType_HALOutput` (AUHAL), `AudioObject*` API для устройств | Полный контроль каналов, буфера, частоты; единый IOProc на дуплексном устройстве → вход и выход на одних часах; создание агрегатного устройства через `AudioHardwareCreateAggregateDevice` |

| Сессии | Пакет-каталог `.ssmtsession`: `manifest.json` (Codable) + бинарные `Float32` блобы | Читаемо, диффуемо, быстро грузится |
| Отчёт | `ImageRenderer` (SwiftUI → PNG/PDF), Core Graphics PDF context | Без зависимостей, тот же код графиков, что и в UI |
| Локализация | String Catalog (`Localizable.xcstrings`), ru + en, переключатель в настройках | Нативный механизм Xcode 15+ |
| Тесты | XCTest; снапшоты — собственный хелпер на `ImageRenderer` + попиксельное сравнение с допуском | Без `swift-snapshot-testing` |
| Проект | XcodeGen (`project.yml`) + Swift Packages | Только build-time, в бинарник не попадает |
| CI | GitHub Actions (репозиторий публичный → раннеры, включая macOS, бесплатны): Linux-тесты ядра + macOS-тесты на Accelerate + universal-сборка `.app` | Бесплатно и без потери качества: ядро тестируется на обеих платформах, приложение собирается на настоящем macOS (см. R1) |

### 3.1 Потоки и данные

```
[IOProc, RT-поток]  генератор → лимитер → fade/gain → выход
                    вход mic/ref → peak/clip-детектор → ring buffer (SPSC)
                    (никаких аллокаций, локов, Swift-рефкаунтинга, логов)

[MeasurementActor]  читает ring buffer блоками → MultiWindowAnalyzer (Welch по 4 окнам)
                    → снимок MeasurementSnapshot (immutable struct) каждые ~50 мс

[WizardModel @MainActor] ← AsyncStream<MeasurementSnapshot> → UI / мини-окно / отчёт
```

- Генератор живёт **в** аудио-колбэке (предвычисленные коэффициенты, xorshift-PRNG), чтобы в режиме B референсом служил ровно тот отсчёт, который ушёл на выход. Сгенерированный сигнал пишется в отдельный ring buffer вместе с номером отсчёта.
- **STOP:** атомарный флаг, читаемый в начале каждого колбэка → выход обнуляется в тот же буфер (задержка ≤ 1 буфера + выходная латентность устройства, обычно < 10 мс). Без fade — сознательно. Горячая клавиша Esc глобально в приложении + кнопка в главном окне и мини-окне.
- Движок измерения — синглтон уровня приложения, не привязан к окнам: сворачивание, закрытие главного окна, мини-панель — не трогают усреднение.

### 3.2 Мульти-оконный FFT
- 4 параллельных Welch-анализатора (65536 / 16384 / 4096 / 1024 при 48 кГц), окно Hann (опц. Blackman-Harris), перекрытие 75 % по умолчанию.
- Накапливаются комплексные `Gxy` и вещественные `Gxx`, `Gyy` (а не H) — это правильное усреднение для H и γ².
- Перевод на сетку 24 ppo: суммирование `Gxy/Gxx/Gyy` по бинам внутри полосы ppo; там, где полоса уже бина (НЧ на коротком окне), — интерполяция.
- Сшивка: каждой ppo-точке назначается окно по диапазону; на стыках — кроссфейд весов в ±1/6 окт. по спектральным плотностям (до деления), что исключает разрывы. Тест: на синтетической системе с известным H отклонение на стыках < 0.1 dB / 1°.
- Периодический «быстрый режим»: период = 65536, синхронное усреднение во временной области одним длинным FFT, затем дробно-октавная сетка. γ² не считается; качество — по разбросу между периодами (оценка SNR).

### 3.3 Delay finder
GCC-PHAT на блоке 2^18 отсчётов (≈5.5 с при 48 кГц) — покрывает поиск до 500 мс с запасом, параболическая интерполяция пика для субсэмпловой точности, метрика уверенности = пик / второй пик. Результат блокируется (delay lock) и показывается в мс и метрах (c = 331.3 + 0.606·T).

## 4. Режим референса — предложение

**По умолчанию — режим B (внутренний референс) с блокировкой задержки на всю сессию.** Пользователь подключает один микрофон и один выход. Никаких кабелей loopback.

Почему это не теряет точности:
1. Референс — это отсчёты, ровно те, что ушли в ЦАП. АЧХ ЦАП/АЦП карты (±0.1 dB в 20–20k) несущественна. Когерентность считается честно, т.к. шум случайный.
2. Латентность «генератор → ЦАП → … → АЦП» постоянна, **пока AUHAL не перезапускался** и вход/выход на одних часах. Поэтому: движок запускается один раз в начале мастера и не останавливается до конца (шум глушится, поток — нет). При перезапуске/смене устройства задержка автоматически перезамеряется, а сравнение «саб ↔ топы» помечается недействительным.
3. Для выравнивания саба нужна только разница прихода. Важная тонкость, которую надо реализовать явно: **задержка находится один раз и замораживается** (на шаге 1 по всей системе), и тот же сдвиг применяется к замерам «только саб» и «только топы». Если искать задержку в каждом замере заново, разница времён прихода саба и топов будет потеряна — это классическая ошибка.
4. Защита: если вход и выход на разных устройствах (разные часы) — режим B запрещён без агрегатного устройства с drift-correction, и мастер предлагает либо создать агрегат одной кнопкой, либо перейти в режим A.

**Режим A (аппаратный loopback)** — опция «Максимальная точность / диагностика»: нужен, если карта нестабильна (dropout'ы), при раздельных устройствах или для независимой проверки. Плюс — абсолютная латентность тракта, видимая в «Эксперте».

**Режим C (внешний референс, музыка)** — в v1 только архитектурно: источник референса — протокол `ReferenceSource` (`.generated`, `.inputChannel(n)`), анализатор уже работает с произвольным сигналом. UI для C — в roadmap.

Итог для пользователя на шаге 0: выбрать карту → выбрать вход микрофона → выбрать выход → «Проверить». Всё остальное автоматически.

## 5. Алгоритмы (замечания к ТЗ, реализуем как описано)

### 5.1 Выравнивание саб ↔ топы
Реализуем шаги 1–7 раздела 6 ТЗ. Дополнения:
- **Знак задержки.** τ может получиться отрицательным (саб приходит позже топов). Тогда карточка говорит «Задержите **топы** на X мс» с пояснением, что это сдвигает всю систему относительно других источников. Это решается вопросом Q3.
- **Ошибка на целый период (cycle slip).** В узкой полосе перекрытия J(τ) почти периодична с периодом 1/fc, соседние максимумы на ±1/fc часто отличаются < 10 %. Если применять правило «< 10 % → неоднозначно» буквально, предупреждение будет почти всегда. Предлагаю: (а) кандидаты ограничиваются окрестностью грубой IR-оценки ±0.5/fc; (б) второй кандидат на соседнем периоде сравнивается по J в расширенной полосе (±1 окт.) и по групповой задержке; (в) «неоднозначно» — только если и после этого разница < 10 %. Альтернатива показывается пользователем в карточке.
- **Уровень:** медианы |H_s| и |H_m| в полосе перекрытия по ТЗ; знак «саб −2.5 dB» = изменение уровня саб-группы.
- Сложность: 2 × 2881 × ~50 точек — микросекунды, перебор полный.

### 5.2 EQ
По разделу 7 ТЗ: энергетическое усреднение с весами γ², σ по точкам, рабочий диапазон, пресеты кривых, правила защиты, жадный подбор RBJ-PEQ + Nelder–Mead с регуляризацией, разделение фильтров по группам, предсказание, лимит 2 итераций, оценка 0–100. Численные значения пресетов — в `ASSUMPTIONS.md`.

### 5.3 SPL
Чувствительность мВ/Па или dBFS@94 dB, либо калибратор (94/114 dB, 1 кГц). Взвешивания A/C/Z — IIR по IEC 61672 (билинейное преобразование, проверка по таблицам допусков класса 1 в тестах). Lpeak = LCpeak, Lmax = LAFmax (Fast, 125 мс).

## 6. Экран запуска и переход логотипа

**Подход: одно окно, два состояния.** `matchedGeometryEffect` не работает между разными окнами, а анимация рамки отдельного безрамочного окна в угол другого окна даёт рывки и мерцание. Поэтому:

1. При холодном старте открывается главное `NSWindow` с `fullSizeContentView`, прозрачным заголовком и чёрным фоном (`#0A0A0B` задаётся и окну, и `NSHostingView`, иначе бывает белая вспышка первого кадра). Окно центрируется в размере ~ 960×640.
2. Корневой SwiftUI-вид: `ZStack { MainShell (opacity 0) ; SplashLayer }`. В Splash полный логотип по центру, тонкий индикатор и версия.
3. Параллельно `AppBootstrap` (async): разрешение на микрофон, перечисление устройств, загрузка настроек/калибровок/последней сессии, прогрев FFT-сетапов vDSP, предзагрузка шрифтов. Показ = `max(1.6 с, время инициализации)`; после 4 с появляется индикатор «Загрузка…» с этапом.
4. Переход 0.75 с, `easeInOut`: знак логотипа связан `matchedGeometryEffect(id: "brandMark")` между центральной позицией и слотом в левом верхнем углу (рядом с «светофорами» окна). Надпись SOUNDSOLUTIONS — отдельный слой, затухает и масштабируется вместе со знаком (поэтому нужен знак и надпись раздельно — см. Q4). Панели — `opacity 0→1` + `offset y 8→0` со ступенчатой задержкой 40 мс. Окно одновременно анимирует размер до сохранённого.
5. «Уменьшить движение» (`accessibilityReduceMotion`) → только кроссфейд 0.4 с без перемещения.
6. Заставка только при холодном старте (флаг в `AppDelegate.applicationDidFinishLaunching`); `applicationShouldHandleReopen`, восстановление из Dock и повторное открытие окна — без заставки. Настройка «Показывать заставку» (по умолчанию вкл.).
7. Логотип в углу — кнопка «О программе». Тот же ассет — в иконке приложения (`AppIcon`), в мини-окне и в шапке отчёта.
8. Логотип используется **только из предоставленного файла**, без перерисовки и перекраски. Если придёт растр — использую его в максимальном разрешении и попрошу вектор.

## 7. Дизайн-система

- Фон `#0A0A0B`, панели `#121316`, рамки — hairline `#FFFFFF` с alpha 0.10–0.18, «металл» — вертикальный градиент рамки 0.22→0.08.
- **Гамма по решению заказчика: оранжевый / жёлтый / чёрный.** Основной акцент — сигнально-оранжевый `#FF6B1A` (действия, активное состояние, основная кривая), оранжево-красный `#FF4419` — «под напряжением» (шум включён, идёт замер), сигнально-жёлтый `#FFC21A` — вторичный акцент, когерентность, предупреждения в паре с чёрными полосами «hazard».
- Ошибка/клиппинг — красный `#FF2D3D`, всегда с иконкой ⛔ и словом (CLIP/КЛИП), чтобы не путать с оранжево-красным. «Хорошо» в светофоре — `#4BE08A` только на статусах (с ✓ и текстом). Холодный голубой `#4CC9F0` — только для сравнительных данных (предсказание), никогда для статусов.
- Формы: срезанный угол 10 px (кастомный `Shape`), glow активного элемента (`shadow` акцентом, радиус 6), сканлайны — оверлей с alpha 0.03, отключаемый.
- Шрифты: **JetBrains Mono** (цифры, табличные, кириллица) + угловатый гротеск с кириллицей для заголовков — кандидаты **Exo 2** или **Russo One** (оба OFL). Окончательный выбор — на этапе 5 со скриншотами.
- Режим «Сцена»: числа ×2, только карточки и STOP, толщина линий ×2, акцент без полупрозрачностей.
- Доступность: контраст текста ≥ 4.5:1 (AA), каждый статус = цвет + иконка + слово, все действия с хоткеями (Space — Capture, Esc — STOP, ⌘→/⌘← — шаги, ⌘M — мини-окно, ⌘E — Эксперт, ⌘L — Сцена).

3. **Отрицательная задержка.** Если саб приходит позже топов — рекомендовать задержку топов (стандартно) или другие варианты (переставить саб, задержка нужна на всех топах + филлах)? Шаг задержки по умолчанию — 0.01 мс?

6. **Распространение.** Developer ID + нотаризация, Mac App Store (песочница, ограничения на агрегатные устройства) или пока только локальные dev-сборки?
7. **Конфигурация системы в v1.** Только «L/R топы + саб-группа, измеряем одну сторону»? Кардиоидные/end-fire саб-массивы, фронт-филлы, делеи — вне v1?
